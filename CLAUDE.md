# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

A single-binary Go reimplementation of `truongpx396/nexus-agent` (a multi-tenant, production-grade AI agent platform) that keeps every architectural seam and control but collapses deployment topology. Go 1.26, Postgres + PgBouncer + Redis, React web app in `web/`.

## Commands

```sh
make build                      # bin/nexusd, bin/nexusctl, bin/signerd
go test ./...                   # = make test: unit + property tests, no external services
go test ./kernel -run TestName -v                                  # single test
go test -race -tags=integration ./...                              # integration (CI runs this)
go test -tags=integration ./tests/integration -run TestName -v     # single integration test
golangci-lint run --build-tags=integration ./...                   # what CI runs (v2.15.0)
make eval                       # eval release gate (also a CI job)
make pr-size                    # changed lines vs origin/main; CI's pr-size workflow fails above 1000 (see Conventions)
go build ./... && go vet ./... && golangci-lint run --build-tags=integration ./... && go test ./...   # pre-"done" check
```

- `make lint` omits `--build-tags=integration`, so it skips integration-tagged files that CI lints. Use the command above. CI pins golangci-lint v2.15.0 (`.github/workflows/ci.yml`); a differently-versioned local binary can report findings CI won't. golangci-lint refuses to run when it was built with an older Go than `go.mod`'s `go` directive, so bump the pin whenever that directive moves past the Go the pinned release was built with. `govulncheck` runs against the exact Go patch `go.mod` names (`setup-go` reads it), so keep that directive on a patched release: nothing bumps it for you (Dependabot raises `go` only when a dependency needs a newer Go), so a weekly `govulncheck` workflow goes red the week a patch ships, and the fix is to raise that line by hand.
- Integration tests start their own disposable Postgres + PgBouncer (testcontainers): Docker must be running, `make up` is not needed. They are the fastest, cleanest signal when runtime behavior looks wrong — prefer them over debugging the long-lived local stack.
- Live-model evals are behind the `liveeval` build tag. Correctness tests never call a live model; they use `internal/provider/fake`.
- CI also runs `govulncheck`, and `npm run lint` + `npm run build` in `web/`.

Run locally: `make up && make migrate && make seed && make run`, then, in another shell, `export NEXUS_HTTP_ADDR=http://localhost:8085 NEXUS_TOKEN=$(make -s token | awk '/^token:/ {print $2}')` and `./bin/nexusctl run "..."` (`make token` prints three lines, and `NEXUS_HTTP_ADDR` is a listen address for `nexusd` but a URL for `nexusctl`). `make run` starts signerd + `nexusd --dev` (fake provider unless `.env` sets `NEXUS_PROVIDER`, auto-generated keys in `.dev/`); without `--dev`, `serve()` fails closed on any unset security-critical config. Config is `NEXUS_*` env vars; `.env` is auto-loaded by `internal/dotenv` (a real env var always wins) and `.env.example` documents every variable. Ports: Postgres 5433 (direct — admin/migrations only), PgBouncer 6432 (runtime), Redis 6380, nexusd 8085. Observability/LLM/pprof stacks have their own `make` targets (see Makefile `##` comments and `docs/`).

Web: `cd web && npm ci && npm run dev | lint | build` (oxlint, `tsc -b`).

**Trap:** a stray Docker container (`nexus-agent-demo-nexusd-1`) can publish :8085 and silently shadow the native `nexusd` — symptoms look like real regressions (404 on a new route, 401 on a fresh token). Check `docker ps` before assuming a code change broke something. A stack reset: `docker compose -f deploy/docker-compose.yml down -v`, regenerate `.dev/*.key`, `make up && make migrate && make seed`.

## Governing documents

`.specify/memory/constitution.md` holds the nine principles and is the code-review checklist; where a plan or design conflicts with it, the constitution wins. `docs/constitution.md` holds the same text (plus its amendment-history comment) and is cited by code comments — keep the two in sync. Read it before design or architecture changes. Spec Kit skills (`/speckit-specify`, `-plan`, `-tasks`, `-implement`, …) live in `.claude/skills/`.

`README.md` is the architecture narrative; `specs/` is the single source of truth for what is built and what is open (`specs/README.md` is the index). The build ledger `docs/build-phases.md` is deleted: its task ids live on as `(bp N.M)` in the specs' `tasks.md`. Code comments and test names cite "Phase N" / "task N.M"; `specs/README.md` says where each resolves, and `tests/contract/specs_test.go` fails if one does not, or if a done task names a file that no longer exists, so move a file and fix its task in the same change.

## Architecture

`nexusd` is one process containing the control plane, the data plane, and the REST surface. The control-plane/data-plane split is a Go interface (`internal/controlplane.Port`), not a network boundary, so a physical split later is a `main.go` change.

**Run path.** A surface (REST through the per-feature `rest` packages mounted on the `internal/surfaces/rest` kit, `nexusctl` via `internal/surfaces/cli`, plus Telegram/Zalo/email/cron/MCP) only translates I/O. `POST /v1/runs` goes to the `runs.Starter` interface (`internal/runs` holds the request/event types, the `Starter`/`Resumer` ports, and the `Launcher` use case — admit a session through `controlplane.Port`, mint its key, start the run — that REST, Telegram, Zalo and email share; Postgres adapters live in `internal/runs/postgres`, which also holds the `runs.Reader` that REST's GET endpoints read through); its only implementation is `kernelRunStarter` in `cmd/nexusd/runner.go`, which is the one place a `kernel.RunState`/`RunConfig` is built. `kernel.Kernel` (`kernel/loop.go`) is the only place agent control flow lives: an `iter.Seq2` generator over `provider.Provider` (one port, one normalized stream; `fake/`, `anthropic/`, router, failover) and `ToolExecutor` (the `internal/tools` 16-step pipeline and `internal/permissions` 10-layer chain, adapted to the port by `internal/tools/kerneladapter`). Cancel/steer/resume/fork go through `internal/runctl`; `internal/queue` is the durable job queue (Redis Streams adapter and the session lock in `internal/queue/redis`) with per-session-key serial locking, drained by workers started in `cmd/nexusd/background.go`.

**State.** Conversation state is an append-only event log. The model lives in `internal/eventlog` (no persistence); the kernel writes it only through the `kernel.EventLog` port (`kernel/ports.go`), whose adapters are `internal/eventlog/postgres` (production — `internal/store` underneath) and `internal/eventlog/inmem` (tests: the loop runs with no database — `kernel/loop_test.go`). Both pass the contract suite in `internal/eventlog/logtest`, so add a port method there too. In Postgres: a trigger rejects UPDATE/DELETE for every role, payloads are envelope-encrypted per tenant (`internal/crypto`; erasure is crypto-shredding, never deletion), and derived tables are projections of the log. Every appended event also gets a hash-chained audit receipt signed by `signerd` over a unix socket — only `cmd/signerd` may hold the private key, and `nexusd` cannot append events unless signerd is reachable. Every `tool_use` must be paired with a `tool_result` before the next model call (property-tested in `tests/property/`). Services that write outside a live run (`oversight`, `runctl`, `delegate`, `teams`, `plan`) each own a unit-of-work port: `Store.InTenant(ctx, tenantID, fn func(ctx, tx Tx) error)` commits or rolls back, and the service's `Tx` embeds `eventlog.Appender`, `eventlog.SessionRows` and `crypto.Keys` (all implemented once by `internal/eventlog/sealed.Unit`) plus its own tables — so a status change and the event that records it commit together or not at all. `internal/runstate` is the one place that rebuilds a `kernel.RunState` from a session's history. Add a new such service the same way, with an in-memory `Store` for its unit tests.

**Tenant isolation.** Two DB roles: `nexus` (superuser, direct to Postgres, migrations only) and `nexus_app` (NOBYPASSRLS, through PgBouncer in transaction pooling, everything at runtime). Scoping is transaction-local — `set_config('app.tenant_id', $1, true)` in `internal/store/tenant.go` — never session-level, because the pooler reassigns connections between tenants. Every tenant table has RLS enabled **and forced**.

### Rules that are enforced mechanically (so follow them up front)

- **Import boundaries** (`tests/contract/boundaries_test.go`; a forbidden path forbids its whole package tree, and most rules are transitive, so an indirect import also fails): `kernel/` must not import `internal/surfaces`, `internal/controlplane`, `internal/tools` (the pipeline reaches it through `internal/tools/kerneladapter`) or an `internal/eventlog/{postgres,inmem}` adapter, and must not reach `internal/store`, a database/cache driver, `net/http`, `os/exec`, the OpenTelemetry SDK, the profiler or a container SDK at all. So every package it imports for vocabulary keeps its I/O in an adapter subpackage (`internal/cost/{postgres,redis,inmem}`, `internal/obs/{otlp,langfuse,profiling}`, `internal/hooks/{exechook,httphook}`, `internal/eventlog/{postgres,inmem}`). 33 core and feature packages carry `noInfra` (no store, database or cache driver, HTTP client — `golang.org/x/oauth2` included — child process, telemetry SDK, profiler or container SDK, even transitively; `noStorage` adds the surfaces and a few more to the database half); `sandbox` is the named exception to it, with its reason in the test. `internal/eventlog` imports nothing from this module and no driver; surfaces must not import `kernel/`; `controlplane` must not import `sandbox`/`memory`/`provider`; the three `cmd/*` binaries must not import each other; `cmd/nexusd` must not import `internal/audit/signerkey` (the private-key package — nexusd signs only through `audit.SignerClient`). `cmd/nexusd` is the composition root and the one package allowed to import both `kernel` and the surfaces.
- **Modules** (`tests/contract/modules_test.go`, `composition_test.go`, `ownership_test.go`): this is a modular monolith packaged by feature, hexagonal inside each feature. A feature is `internal/<feature>/` (vocabulary, use case, the ports it needs) with its storage in `<feature>/postgres` (or `redis`, `inmem`, `oauth2`) and its driving adapters beside it: `<feature>/rest` for HTTP (mounted on the kit in `internal/surfaces/rest`) and `<feature>/tool` for the model-facing tools. (1) **An adapter is its feature's own**: it may import its feature, the domain and the persistence kit (`internal/store`, `audit/postgres`, `crypto/postgres`, `eventlog/sealed`), never another feature's adapter; when two features must write in one transaction, `cmd/nexusd` injects the writer (`runspg.Sessions{Budgets: costpg.CreateBudget}`, `planpg.New(..., delegatepg.CreateEnvelope)`, `cryptopg.Eraser{Artifacts: toolspg.DerivedArtifacts{}}`). (2) **Feature-to-feature imports are declared** in `allowedFeatureImports`, which also lists every `rest` and `tool` binding; a new edge fails until you add it, with a reason, in the diff. A binding imports its feature directly and never storage or the kernel directly, so there is no translation layer for you to write in `cmd/nexusd`. (3) **`cmd/nexusd` wires; it holds no SQL**, operator commands included: a query belongs in the package that owns the table (`tenancy`, the cost adapter, ...), a use case in the feature that owns it (`runctl` owns the checkpoint, the idle sweep, orphan recovery and `Send`; `oversight` owns `Decisions`). (4) **Every table has one owner, and SQL stays in it**: add a table to `tableOwners` in `ownership_test.go` in the same change as its migration, and put its queries in the owner's package; `sessions`/`events` are the shared kernel and list each accessor with a reason, and `reporting/postgres` may read but not write. Do not add a column to `sessions` or a foreign key into it: what a feature records about a session goes in the feature's own table keyed by `session_id` (no `REFERENCES sessions`), as `team_members`, `session_lineage`, `session_forks` and `plan_sessions` do; `tests/integration/session_migration_test.go` pins the exact column list and the foreign keys against the real schema. (5) A feature that needs to know a session settled implements `runctl.SettledObserver`; it is registered once in `cmd/nexusd/compose.go`. A new event type is added to `internal/eventlog/event.go` and given an owner in `taxonomy.go` (the list stays closed on purpose; see that file). When you add a feature, give it a package, a `postgres` adapter, its tables' SQL, and an in-memory `Store` for its unit tests; do not add SQL to `internal/store` or `cmd/nexusd`. The shared kernel is deliberate: the session/event aggregate (`internal/eventlog`, the `sessions`/`events` tables every feature table refers to by session id), `crypto`, `audit`, the provider port, and the persistence kit.
- **Exhaustive switches**: switches over `kernel.TerminalReason` and response classification must list every case — `exhaustive` runs with `default-signifies-exhaustive: false`, so a `default:` does not satisfy it. Add the case.
- **No float in money**: `internal/cost` uses integer money; `money_notfloat_test.go` fails on any `float32`/`float64` token anywhere in the package tree (adapters included).
- **File size**: a non-test Go file may not exceed 500 lines (`tests/contract/filesize_test.go`; `_test.go` and generated files are exempt, and `lineCapExempt` is empty on purpose). When you cross it, split by responsibility — see Conventions.
- **Goroutine leaks**: a package whose non-test code starts a goroutine and that has tests must declare `func TestMain(m *testing.M) { goleak.VerifyTestMain(m) }` (a `leak_test.go`; `tests/contract/goleak_test.go`, and `leakCheckExempt` is empty on purpose). A test that trips it fixes the test, not the check: cancel the context or close the client in a `t.Cleanup`. `provider.Stream` has no `Close`, so cancelling the context is how a stream a test does not drain is released. `go test` in CI also runs with `-shuffle=on`; a failing package prints its seed, and `-shuffle=<seed>` reproduces it.
- **Lint bans**: `fmt.Print*` outside `cmd/` (log with zerolog via `internal/obs`; the lint message says slog, but the codebase uses zerolog) and `math/rand` anywhere (use `crypto/rand`).
- **Lint, beyond the standard set** (`.golangci.yml`): `errorlint` (match with `errors.Is`/`errors.As`/`errors.AsType`, wrap with `%w`, never `err == sentinel`), `errname` (a sentinel is `ErrX`, an error type is `XError`), `predeclared` (never name a local `max`, `min`, `new`), `modernize` (`slices`, `maps`, `strings.SplitSeq`, `errors.AsType`, range over int, `omitzero`), `forbidigo` (no `fmt.Print*` outside `cmd/`, no `math/rand`, no package `sort`: use `slices.Sort`/`slices.SortFunc` with `cmp.Compare`), `perfsprint` (`errors.New` for a message with nothing to format), `intrange`, `copyloopvar`, `nolintlint` (a `//nolint` that suppresses nothing fails, so delete the directive and keep the reason as a plain comment), `unconvert`, `usestdlibvars`.
- **A response never carries an infrastructure error.** A handler that fails on a database, queue or dependency calls `restkit.ServerError(w, r, "<operation>", err)` (the cause goes to the log, the client gets `<operation>: internal error`); a webhook or probe outside the kit logs and answers the same way. An error that means something to the caller keeps its own status and text, and the use case says which with a sentinel wrapped by `%w`, never by its status or its words: a binding matches it with `errors.Is` (`runctl.ErrSessionNotFound`, `ErrSessionState`, `ErrInvalidArgument` map to 404, 409, 400; `contentaccess.ErrNoGrant` to 403), and anything else is an infrastructure failure. Read a request body with `restkit.DecodeJSON`; the kit bounds every body at 4 MiB and answers 413 past it. A `ReadAll` of untrusted input (a response, an upload, a decompressor) goes through `io.LimitReader`, and a client that reaches a model or the network never has `http.DefaultClient`'s "no deadline at all" (the providers bound the wait for response headers, not the stream).
- **No build-stage names**: `tests/contract/naming_test.go` fails on a file name, a Go identifier or a Go string literal containing "phase" (`phase6Rig`, `"phase2-v1"`); name it for what it is. Comments are exempt: the `Phase N` citations are the traceability convention `specs_test.go` checks.
- **Telemetry is content-free**: span attributes pass a deny-by-default allowlist (`internal/obs/allowlist.go`). Never put prompt or tool content into spans or logs.
- **Optional hooks are nil-valid** (`Kernel.Stuck`/`Tracer`/`OnChunk`, and the Postgres event log's `Hooks.Chain`/`Suspend`/`Delegate`): nil means "that control isn't wired", which is how minimal kernels are built in tests. New hooks must follow that convention.

## Conventions

- Split large Go files by responsibility **within the same package** (e.g. `cmd/nexusd`: `infra.go`, `compose.go`, `ports.go`, `cli_*.go`; `kernel`: `turns.go`, `events.go`, `terminal.go`) — never into a new package or sub-package; the boundary test is package-granular and the repo already follows this. Aim for ~150–400 lines per file (500 is the enforced cap, above), copy the full import block and run `goimports -w` to prune. `kernel/turns.go` → `kernel/metering.go` is the worked example: a pure move, verified with `go build` and the package's tests.
- **Changes are spec-driven.** `specs/` is the source of truth (`specs/README.md` is the index and says how work flows). A change to behaviour-bearing code (non-test Go under `internal/`, `cmd/`, `kernel/` and `evals/`, SQL migrations, the eval corpus, `web/src/`) must come with a change under `specs/`: a new feature starts with `/speckit-specify` (then `-plan` and `-tasks`); anything else adds or checks off a task in the relevant spec's `tasks.md`, naming the files it touched (`tests/contract/specs_test.go` fails if a done task names a file that no longer exists, so move a file and fix its task in the same change). `make spec-gate` is the check CI's `spec-gate` workflow enforces. A PR that genuinely needs no spec (a comment-only edit, a rename the specs already describe) carries the `no-spec` label and says why in the description. Run `/speckit-converge` before a release: it finds what the specs say is built and the code does not do.
- Keep PRs under **1,000 changed lines** (insertions + deletions; lockfiles, `web/dist`, `evals/testdata/baseline.json` and the vendored Spec Kit scaffolding don't count). `make pr-size` measures your branch; `.github/workflows/pr-size.yml` fails the PR above the limit. Split a bigger feature into stacked PRs. A change that is big but mechanical (a rename, a file split) gets the `large-pr` label and a sentence in the description saying why. The limit and exclusions live in `scripts/pr-size.sh`.
- **Opening a PR is not done until CI is checked.** After `gh pr create`, and after every later push to the PR, run `gh pr checks <n> --watch` (in the background if you have other work) and report each check's outcome. `skipped` is not `passed`: `unit`, `integration` and `eval-gate` are skipped whenever `lint` fails, because they `need` it. On a failure, read `gh run view <run-id> --log-failed` and say whether this PR caused it or `main` was already red (`gh run list --branch main --workflow ci --limit 1`). Never write "CI is green" without having seen it. A `PostToolUse` hook on `gh pr create` injects this reminder with the PR number; pushes to an existing PR rely on this rule alone.
- Prompts, tools, skills and models are production config: changing one is a deploy and must clear the eval gate.

Path-specific rules for `migrations/` and `evals/` are in `.claude/rules/`.

## Claude Code setup

`.claude/settings.json` is shared: a permission allowlist for the verification commands above, deny rules for secrets (`.env`, `.dev/*.key`, `.dev/signer/`, `*.pem`), destructive commands (`docker compose … down -v`, force-push, `git reset --hard`) and hand-editing `evals/testdata/baseline.json`, plus three hooks in `.claude/hooks/`: after a Go edit, `goimports -w` and a nudge if the file passed the line cap; before `gh pr create`, an advisory PR-size check; after it, a reminder to verify CI. The hooks need `jq`, and `goimports` (`go install golang.org/x/tools/cmd/goimports@latest`) for formatting. Personal overrides go in `.claude/settings.local.json` (gitignored). Read denies stop the Read tool only, not `cat` through Bash.
