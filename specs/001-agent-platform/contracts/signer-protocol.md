# Contract: Signer protocol and the audit chain

**Plan**: [../plan.md](../plan.md) | **Spec**: FR-052, FR-053, FR-054 | **Source**: `cmd/signerd`, `internal/audit/{protocol,signer,chain,anchor,verify}.go`, `internal/audit/signerkey`

`signerd` is the sign-only custodian of the audit key. `nexusd` may **ask** it to sign a digest and may fetch the **public** half; it can never
read the private key. This is a structural property of the build, not a convention: `internal/audit/signerkey` is importable only by
`cmd/signerd` (`tests/contract/boundaries_test.go`: *`cmd/nexusd` must not import `internal/audit/signerkey`*; the three binaries must not import
each other). `nexusd` **cannot append an event unless `signerd` answers** — it fails closed.

## Wire protocol

Transport: a **unix socket** (default `.dev/signerd.sock`, `NEXUS_SIGNERD_SOCKET`). Framing: **one newline-delimited JSON request per
connection, one newline-delimited JSON response back**, then the connection closes. A fresh dial per call is deliberate — a local socket makes
anything richer (framing, multiplexing, an RPC codec) needless complexity. The protocol package has zero dependency on `signerkey`.

```jsonc
// Request                                     // Response
{ "op": "sign", "digest": "<base64, 32 bytes>" }   →  { "signature": "<base64>", "key_id": "…" }
{ "op": "public_key" }                              →  { "public_key": "<base64>", "key_id": "…" }
                                                       { "error": "…" }      // on any failure; every other field empty
```

- `OpSign` / `OpPublicKey` are the only operations. A caller checks only `error`; it never has to distinguish a transport failure from an
  application one at this layer.
- Algorithm: **Ed25519**. The key lives at `NEXUS_SIGNER_KEY_PATH` (default `.dev/signer/ed25519.key`), loaded or generated by `signerd`.
- `audit.Signer` (`Sign(ctx, digest) (sig, keyID, err)`, `PublicKey(ctx) (pub, keyID, err)`) is the interface; `SignerClient` is the unix-socket
  implementation. A KMS/HSM adapter would satisfy the same interface.

## Receipt construction (`chain.go`)

One receipt per **durably appended event**, written **in the same transaction** as the event (via `kernel.ReceiptFunc`), so an event is never
observable without a receipt. Chained **per session** over **plaintext digests** — never the payload — so a lawful crypto-shredding erasure
never breaks verification.

```
hash = SHA-256( prevHash(32) ‖ tenantID(16) ‖ sessionID(16) ‖ seq(8, big-endian) ‖ eventID(16)
                ‖ len(eventType)(4, big-endian) ‖ eventType ‖ payloadDigest(32) )
```

`prevHash` is a fixed 32-byte zero **genesis** for a session's first receipt (a fixed-width encoding, so two different inputs can never
collide through delimiter concatenation). The receipt stores `hash`, `signature` (over the hash), `signer_key_id`, `prev_hash`, plus
`receipt_seq` (a global, per-tenant-queryable sequence). `UNIQUE (session_id, seq)`.

## Anchors (`anchor.go`)

`Chain.Anchor(ctx, tx, tenantID) (Anchor, created bool, error)` covers every receipt written since the last anchor `(from_receipt_seq,
to_receipt_seq]`, chains to the previous anchor's hash, and signs it. It runs as **its own pass** — a ticker in `cmd/nexusd/background.go`,
or `nexusd verify-chain` — deliberately *not* inside any event's transaction, so it is an independent checkpoint. `created=false` (nothing new)
is the normal, frequent case for an idle tenant.

## Verification (`verify.go`)

`Chain.Verify(ctx, tx, tenantID) (Report, error)` replays every receipt and anchor, recomputes each hash, verifies each signature against the
public key, and cross-checks receipts against events. `Report{Breaks, Gaps}`; **`OK()` ⇔ no breaks and no gaps**.

- **Break**: any hash or signature mismatch (`SessionID` zero for an anchor-level break).
- **Gap**: an event with no matching receipt — "an event reached the log without the chain being extended".
- Any non-empty `Breaks` or `Gaps` is the alert condition. `receipts` and `anchors` are append-only (trigger + `REVOKE UPDATE, DELETE`).

## What this does and does not defend against

| Threat | Defended? |
|---|---|
| A component that writes receipts rewriting one | **Yes** — it cannot sign; it never holds the key |
| Altering, removing from the middle of, or reordering a session's receipts | **Yes** — the chain and signatures break; `Verify` reports it |
| An event appended without a receipt | **Yes** — reported as a gap |
| A lawful redaction (crypto-shredding) | **Does not break** the chain — it is over digests |
| A database superuser who deletes the chain **tail together with its anchors** | **Not demonstrably** — anchors live in the same database; nothing is published outside it (spec Known deviation 5, plan Constitution Check) |
